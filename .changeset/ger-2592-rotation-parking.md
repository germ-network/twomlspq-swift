Rotation staging now follows the book's never-evict rule: the single in-flight candidate slot becomes a 4-slot in-flight window plus a single latest-wins parked slot. A rotation request while the window is full PARKS (it is no longer refused with `.rotationInFlight`), the round still emits its routine self-refresh, and the parked request is auto-proposed on the next routine round once a canonicalization clears the window. A canonicalization clears the whole window at once (losing candidates' authorizations expire with it). A parked rotation surfaces as `.pending` in `myPrincipalState`. Every deterministic rotation refusal (empty id, my own current id, a peer-known id) is now checked before any commit, so an invalid `rotating:` can no longer consume a queued fold and advance the epoch invisibly to the host. One behavior delta follows the earlier check: `rotating:` naming a peer id that was superseded but is still authorized is now refused before the round (it used to be admitted after the fold) — it was never a legitimate self-rotation. Wiring change: `TwoMLSSession.rotationCandidate` is replaced by `rotationCandidates`/`deferredRotationCandidate`; archives gain keys 46/47, and a pre-existing archive's key 31 is decoded as a one-element window.
